Detection Rules

What SNIDS flags

Current thresholds pull from Settings; change them there and they apply immediately.

TCP threat detectors

  • SYN_FLOOD - Excess SYNs without handshakes. Threshold: {{ cfg.syn_threshold }} SYNs / {{ cfg.syn_window_seconds }}s; completion ratio min {{ cfg.handshake_completion_min_ratio }}.
  • TCP_RESET_SPIKE - Burst of RSTs from a source. Threshold: {{ cfg.rst_threshold }} RSTs / {{ cfg.rst_window_seconds }}s.
  • TCP_RESET_FLOW_ANOMALY - Multiple RSTs on the same flow within the window.
  • POTENTIAL_SESSION_HIJACK - Large seq jump (>{{ cfg.hijack_seq_jump }}) or repeated duplicate ACKs in {{ cfg.syn_window_seconds }}s.
  • PORT_SCAN - {{ cfg.port_scan_port_threshold }}+ unique destination ports from one source within {{ cfg.port_scan_window }}s.

Alert cooldown (same dedup key): {{ cfg.alert_cooldown_seconds }}s.

How severities are set

  • SYN flood: scales to high/critical if rate doubles the threshold.
  • RST spike: medium/high based on burst size; flow anomaly is medium.
  • Session hijack: medium for seq jump; low for duplicate-ACK pattern.
  • Port scan: medium; high if well above threshold.

Usage notes

  • Live: Start on Loopback or Wi-Fi/Ethernet; run simulators or browse to generate traffic.
  • PCAP: Upload via Monitoring -> PCAP; same rules apply; session recorded.
  • Drill-down: Monitoring -> Sessions -> View for alerts/packets/CSV per run; Traffic flow filter and packet modal for quick inspection.
